# 电子书导入与笔记对接能力调研

调研时间：2026-09-11。结论已同步到产品界面：书架「导入书籍」入口、以及「导入笔记」弹窗的「平台支持说明」页签。

## 一、要解决的问题

1. 可导入的电子书格式太少，常见的 EPUB 等格式无法导入。
2. 「添加书籍」和「上传文档」是两套割裂的入口：前者能定义封面、书名等信息，后者不能。
3. 平台只做 AI 分析，用户无法在站内阅读原文，费曼学习法与阅读本身脱节。
4. 用户在微信读书、Kindle 等平台的划线笔记无法进入学习闭环。

## 二、电子书格式支持

`src/lib/document-parser.ts` 中的 `SUPPORTED_FILE_TYPES` 为当前支持清单：

| 扩展名 | 解析方式 | 可自动带出的信息 |
| --- | --- | --- |
| `.epub` | jszip 解包 + OPF spine 顺序解析，检测 `META-INF/encryption.xml` 判定 DRM | 书名、作者、简介、封面、章节 |
| `.mobi` `.azw` `.azw3` `.prc` | `@lingo-reader/mobi-parser`，先 `initMobiFile`，失败回退 `initKf8File` | 书名、作者、简介、封面、章节（含 NCX 目录标题） |
| `.fb2` | FictionBook XML 解析 | 书名、作者、章节 |
| `.pdf` | pdfjs-dist 文本层，逐页提取后合并 | 正文（超出单节长度时由阅读器自动分节） |
| `.docx` | mammoth 提取纯文本 | 正文 |
| `.doc` | 内置 OLE 复合文档解析（`src/lib/legacyWord.ts`），读取 `WordDocument` + `0Table`/`1Table` 的分片表还原正文 | 正文；实际是 RTF / HTML 的同名文件按对应解析器处理 |
| `.html` `.htm` `.xhtml` | 去标签、去脚本样式后转为纯文本 | 正文、页面标题（`<title>` 或 `<h1>`） |
| `.rtf` | 内置 RTF → 纯文本转换（含代码页与 unicode 转义处理） | 正文 |
| `.txt` `.md` `.markdown` `.json` | 纯文本 / Markdown 结构 / 已有 JSON 记录 | 正文，Markdown 按标题分节 |

`.doc` 走纯浏览器实现，不新增依赖：先校验 OLE 签名（`D0 CF 11 E0 A1 B1 1A E1`），解析 FAT / MiniFAT / DIFAT / 目录项取出流，再按 FIB 的 `fWhichTblStm` 选择正文表、按分片表（Clx / Pcdt）还原正文，压缩分片按文档代码页（gb18030 / big5 / shift_jis / euc-kr / windows-1252）解码，非压缩分片按 UTF-16LE 解码。Word 6.0 / 95 与加密文档会给出可读的另存建议。

明确不支持、且会给出替代建议的格式见 `UNSUPPORTED_BOOK_FORMATS`：`.djvu`、`.chm`、`.cbz`、`.cbr`、`.azw4`、`.lit`、`.pdb`。每个扩展名都有中文 / 英文的具体转换建议，而不是笼统报错。单文件上限 20MB（`MAX_DOCUMENT_FILE_SIZE`）。

## 三、导入书籍表单

「导入书籍」现在是一个入口解决两件事：解析文件后，书名、作者、简介、封面会被自动预填，用户仍可逐项修改，并补充标签等信息后保存为书籍；EPUB / MOBI 解析出的章节会写入 `Book.chapters`，供站内阅读器与笔记定位使用。封面也可以单独选择图片文件（`src/lib/coverImage.ts`，转 data URL 且限制大小）。

## 四、阅读原文与费曼学习的衔接

站的阅读能力按「常见阅读软件的最小可用集合」对齐，全部围绕纯文本原文实现，不引入 DRM 或私有格式。

- 阅读视图：`src/components/BookReader.tsx` 提供分节阅读、目录、进度条、字号调节（15–28）、三档主题（记忆在 localStorage）、上下节切换与方向键翻节；换书或重新打开时按 `readingProgress` 回到上次位置。
- 划线：选中正文后出现「划线」「划线并写笔记」，四色可选（黄 / 绿 / 蓝 / 粉），结果写入 `NoteRecord`，保留 `quote`、`offset`、`color`、`chapterIndex`、`chapterTitle`、`tags`、`source: 'reading'`。正文里的划线可点击，直接改色、补备注、增删标签或删除；面板中列出全部划线，可跳回原文位置，并支持按章节与标签筛选。
- 标签：标签规则集中在 `normalizeNoteTags`（`src/lib/readerAnnotations.ts`），去空白、忽略大小写去重、单个标签截断到 24 字（`MAX_NOTE_TAG_LENGTH`）、每条划线最多 8 个（`MAX_NOTE_TAGS`）。阅读器与备份导入共用同一函数，输入框用 `datalist` 提示本书已有标签，避免同一主题写成多种写法。
- 定位与对齐：`src/lib/readerAnnotations.ts` 优先按记录里的 `offset` 对齐正文，偏移失效（换版本、重新导入）时回退到在当前节内查找引文，仍找不到的划线只保留在面板里，不会错标到别的句子。
- 书签：工具栏「书签」标记当前这一节，保存位置偏移、章节标题与摘要，可补备注和改颜色；同一节已标记时再次点击打开书签列表而不是重复新增，单本书上限 500 条（`MAX_BOOKMARKS_PER_BOOK`，与备份导入校验同源）。
- 检索：面板中的「检索」在当前书全文里做大小写不敏感匹配，列出命中摘要并跳转到对应节，命中处在正文里同步高亮；单次最多返回 200 个命中，关键词上限 80 字符。
- 笔记与书签：「我的笔记」汇总站内划线、外部导入划线与手工笔记，标注来源（原文划线 / 外部导入 / 手工笔记）与标签，支持按来源和标签筛选；书签在同一页以独立区块展示摘要、备注、章节与颜色，可直接回到原文位置或删除，阅读器书签面板仍保留编辑入口。
- 出处核对：费曼提示词要求 AI 引用原文时标注 `[S#]`、引用用户划线时标注 `[H#]`（`src/lib/feynman-prompts.ts`），`SourceEvidence` 面板对两者都做核对展示。
- 练习门槛：导入过原文的书，需要至少一条划线或笔记才能提交费曼复述，避免 AI 在没有依据时空评。
- 进度区分：书架区分「已读 X%」（原文阅读进度）与「费曼 XX 分」（六阶段进度），两者互不替代（`getBookReadingPercentage` / `getBookshelfProgressPercentage`）。
- 备份兼容：书签、划线偏移、颜色与标签都进入导出 / 导入校验（`src/lib/backupValidation.ts`），标签在导入时按同一套规则重新规整，旧备份没有这些字段时按空值处理，不阻塞导入。

## 五、外部平台笔记对接调研

判定原则：只接入官方对个人开发者开放的能力；官方导出格式通过文件 / 文本导入；没有官方途径的平台不接入，也不做 cookie 抓取或抓包逆向。

### 已接入：官方 API

| 平台 | 官方能力 | 接入方式 |
| --- | --- | --- |
| Readwise | 官方 API，个人访问令牌 | `GET /api/v2/books/` 拉取书籍与划线、笔记，令牌在 readwise.io/access_token 获取 |
| Zotero | 官方 Web API v3，个人 API Key | 拉取条目批注与笔记，自动匹配父条目标题，密钥在 zotero.org/settings/keys 创建 |

### 已接入：官方导出文本

| 平台 | 官方导出途径 | 说明 |
| --- | --- | --- |
| 微信读书 | 「我的笔记」导出笔记 | 无开放平台，仅官方导出，支持 TXT 文本粘贴或文件导入 |
| Kindle | read.amazon.com/notebook 导出，或设备内 `My Clippings.txt` | 无批注 API；导入后位置信息转成「第 N 页 · 位置 X-Y」 |
| Apple Books | 应用内选择笔记后分享为文本 | 无公开 API |
| 得到 | 应用内笔记导出 / 复制 | 无官方 API |
| Google Play Books | Google Takeout 导出 | 无批注 API |
| KOReader | 官方「导出标注」生成 Markdown / 文本 | 自托管同步服务器（AGPL-3.0）属于进阶方案，未纳入默认流程 |

导入适配层在 `src/lib/importAdapters.ts`，统一解析为 `ImportedHighlight` 后去重、按章节匹配、截断到 `MAX_NOTE_LENGTH`，再写入 `NoteRecord`（`source: 'import'`）。弹窗入口在书架与阅读视图的「导入笔记」。

上面的能力对应弹窗里的三个页签：「官方 API」（令牌直连）、「导入文本」（笔记来源下拉 + 粘贴或上传文件）、「平台支持说明」（按下表分组展示每个平台的导出步骤与官方链接）。

「平台支持说明」页签里的导出说明来自 `PlatformCapability.guideZh / guideEn`，官方入口来自 `officialUrl`（没有官方帮助页的平台留空，只写应用内步骤）。卡片按 `PLATFORM_CAPABILITY_GROUP_ORDER` 分三组渲染：官方 API 直连、官方导出导入、暂不接入。「导入文本」页签的「笔记来源」下拉也会带出所选平台的导出步骤与官方链接。

### 暂未接入（界面里合并为「其他平台」一条）

| 平台 | 原因 |
| --- | --- |
| Get笔记（biji.com） | 官方 OpenAPI 需要付费会员，且以 OAuth 授权为主 |
| 有道云笔记 | 官方接口基于 OAuth 1.0a，需要开发者账号审核 |
| 掌阅 / 京东读书 / 番茄 / QQ 阅读 | 未公开面向个人开发者的接口，也没有通用导出格式 |

这些平台在界面里不单独列卡片，统一归到「其他平台」一条，并在说明里点名具体平台与不接入的原因；`importAdapters.test.ts` 会校验这些名字仍然出现在说明文案里。

### 明确不采用

cookie 抓取、模拟登录、抓包逆向类方案（如 wxread-export、Klib、dedao-dl 等）一律不接入：违反平台条款，存在账号封禁与法律风险，与平台是否具备企业资质无关。

## 六、后续可选方向

- 若后续获得有道云笔记、Get笔记的开发者审核资格，可复用现有 `importAdapters` 结构补上 OAuth 接入。
- KOReader 自托管同步服务器可作为进阶选项，需要独立部署与账号体系，暂不进入默认流程。
- 电子书格式可继续评估漫画类 `.cbz/.cbr`（图片为主，需与现有纯文本学习链路分开设计）与 `.djvu` 等扫描格式（需 OCR，成本另计）。
