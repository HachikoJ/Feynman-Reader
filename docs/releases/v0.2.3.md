# v0.2.3

修复 TokenDance 授权返回后仍提示缺少 API Key 的流程：授权得到的 Key 立即加密保存到当前账号，刷新或重新打开设置后仍可读取；数据传输同意仍须单独确认，不会因授权自动赋予。

- 同一授权码只兑换一次，兑换与保存期间禁止提前验证，保留等待期间勾选的数据传输同意。
- 启用 AI 时通过当前账号保存的 Key 验证 TokenDance 连接；回调完成后保留设置页面，授权或保存失败时明确提示重试。
- 导航、登录、引导和默认头像使用用户提供的观猹图标；用户自定义头像优先，普通账号保持原有身份标识。

## 验证与恢复

72 组、549 项测试通过，TypeScript 和生产构建通过。浏览器使用虚构账号与模拟授权，覆盖授权等待、协议确认、加密保存、刷新、启用与再次刷新；授权兑换、密钥保存和余额验证各执行一次，普通设置无明文 Key。观猹图标已检查桌面、手机及亮暗主题。

无数据库结构变更或权限调整。保留 v0.2.2 标签、源码包、旧部署目录及部署前私有备份；回退应用时保留当前数据和服务器配置，参见[版本发布与恢复](../operations/releases-and-rollback.md)。旧页面已经丢失且未保存的 Key 需要重新授权，不能重复使用已消费的授权码。

## English

TokenDance authorization now saves the received key in the current account's encrypted vault before completing the callback. Reopening settings retains the authorization; data transfer consent still requires a separate explicit confirmation. Callback exchange is deduplicated, pending consent changes are preserved, early verification is blocked, and stored keys are validated through the account endpoint before enabling AI.

Supplied Watcha icons identify sign-in entries, onboarding and default Watcha avatars. Custom avatars and generic password-account identities are preserved across light and dark themes.

All 549 tests in 72 suites, TypeScript and the production build pass. Browser verification uses fictional accounts and mocked authorization, including reloads before and after activation, with no plaintext key in ordinary settings. This release changes no database schema or account permissions. Retain current data when rolling back to v0.2.2. Keys lost by the old page before being saved require fresh authorization.
