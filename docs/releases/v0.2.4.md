# v0.2.4

修复 TokenDance 授权返回后被浏览器跨域策略拦截的问题：授权码兑换接口只允许 Content-Type 请求头，现按接口契约发起请求。授权链接的 app_url 和 AI 调用的 X-App-URL 继续使用 https://www.deline.top，应用归因不变。

观猹未返回头像时保留此前保存的头像。用户头像优先于占位图，自定义头像优先级保持不变。当前没有保存头像的账号可以重新登录观猹同步资料；仅在没有可用用户头像时显示占位图。

## 验证与恢复

74 组、563 项测试、TypeScript 和生产构建通过；代码检查无错误，生产依赖审计无漏洞。

真实浏览器对 TokenDance 官方接口的探针已复现修复前的跨域拦截，并确认修正请求头后可正常读取接口响应。探针使用虚构无效授权码，未使用真实账号、Key 或付费 AI 调用。回归覆盖授权码兑换、PKCE 状态、头像同步和登录后头像替换；完整授权流程使用模拟接口验证，真实用户授权仍由本人完成。

本版本没有数据库结构或权限变更。保留 v0.2.3 及部署前私有备份，参见[版本发布与恢复](../operations/releases-and-rollback.md)。更新后刷新页面并重新授权 TokenDance，再确认数据传输并启用 AI。

## English

TokenDance code exchange now sends only the Content-Type header supported by the upstream CORS policy. The previous X-App-URL header blocked browser authorization on mobile and desktop. OAuth app_url and AI request attribution remain https://www.deline.top.

Watcha profile synchronization preserves the previously saved avatar when a subsequent login omits the image. User avatars take priority over placeholders, and custom images retain precedence. Accounts without a saved image can sign in again to refresh provider information.

A live browser probe reproduced the CORS failure and verified readable upstream responses with the corrected headers, using a fictional invalid code. Authorization persistence uses mocked APIs for regression; real account authorization must be completed by the user. No database schema or permission changes. Retain v0.2.3 and private deployment backups for rollback.
