# SafeLine 接入方案

这份文档用于把 SafeLine 放到 `deline.top` 前面，保护公网网页入口，同时保持费曼读书助手的正常使用。项目是静态站，书籍、上传文档和笔记保存在用户浏览器本地，浏览器会直接访问 `api.deepseek.com`；SafeLine 只能保护 `deline.top` 的网页和静态资源，不能代理或读取用户发往 DeepSeek 的请求。

## 推荐拓扑

```text
用户浏览器
    |
    v
SafeLine（公网 80/443）
    |
    v
站点 Nginx（仅内网或本机后端端口）
    |
    v
费曼读书助手静态发布目录
```

SafeLine 和站点 Nginx 不能同时抢占同一台机器的 80/443 端口。优先选择独立的腾讯云实例作为 WAF 节点；如果必须同机部署，应先把站点 Nginx 改成只监听内网地址或本机后端端口，并在腾讯云安全组中禁止公网直接访问后端端口。切换前必须保留原站点入口和最近一次可回滚发布目录。

## 低误报基线

首次接入采用“先观察、再收紧”的策略：

- SafeLine 使用官方稳定版和默认的平衡防护策略，不直接启用严格模式。
- 初期不启用人机验证、身份认证、HTML/JavaScript 动态防护。它们可能改变 Next.js 页面、Service Worker 或 CSP 的行为，静态站没有必要承担这类兼容风险。
- 保持 `GET`、`HEAD` 和正常查询参数可用。项目会使用 `/_next/static/`、`/sw.js`、`/manifest.json`、图片和字体等静态资源。
- 不对 URL、查询参数或响应正文做自定义全局关键字拦截。书名、笔记和 AI 相关文本可能包含引号、代码、括号、中文标点或长文本，简单黑名单很容易误伤。
- 不在 SafeLine 额外设置比当前源站更激进的按 IP 限速。现有 Nginx 已有连接数和请求速率保护，先以真实访问日志为依据调整；同一办公网或校园网的多人共享出口 IP，不能按单个用户理解。
- 不修改缓存策略。`/_next/static/` 的发布资源需要保持可缓存，`sw.js` 需要保持 `no-store`，否则旧页面和 Service Worker 可能出现版本混用。
- 保留源站的安全响应头，并在 WAF 外部验证它们仍然存在。WAF 不应覆盖 CSP、HSTS、X-Frame-Options、Referrer-Policy 等响应头。

## 上线步骤

1. 在服务器侧确认 Docker、磁盘、内存、80/443 端口和 SafeLine 官方版本要求。不要执行来源不明的安装脚本，也不要绕过 HTTPS 证书校验下载脚本。
2. 先创建独立的 SafeLine 节点或内部测试站点。SafeLine 管理端口只允许管理员 IP、VPN 或内网访问，不暴露给公网。
3. 把测试域名指向 SafeLine，并将上游设置为现有站点的内网地址。保留 `Host`、HTTPS 协议和客户端来源信息，后端端口不能被公网安全组直接访问。
4. 在 SafeLine 上先采用平衡防护，不开启动态防护和人机验证。用下面的验证脚本检查真实页面、查询参数、CSS、JavaScript、Service Worker、非 GET 请求和敏感路径。

   ```bash
   bash scripts/verify-safeline-rollout.sh https://测试域名
   ```

5. 用 Safari、Chrome 和移动端各完成一次首次引导、书架打开、文档解析、阶段学习页面加载。AI 请求应继续直接访问 `https://api.deepseek.com`，不能因为 WAF 配置改变 CSP 或浏览器跨域行为。
6. 观察至少一个完整高峰周期的 SafeLine 命中日志和源站 4xx/5xx 日志。对误报只做单条、按路径和条件明确的放行，不关闭整类 Web 攻击防护。
7. 再切换 `www.deline.top` 和 `deline.top` 的 DNS 或入口。切换期间保留旧源站，验证失败时只回退 DNS/入口，不删除旧发布目录。

## 回滚条件

出现以下任一情况就回退入口，不在生产环境临时关闭全部防护：

- 首页返回 SafeLine 挑战页、空白页或非费曼读书助手内容；
- 任一 Next.js 静态资源、`sw.js` 或 manifest 被阻断；
- 首次引导、设置页或书架在主流浏览器中出现持续性加载失败；
- 源站 4xx/5xx、连接数或延迟明显异常，且无法在单条规则范围内解释；
- WAF 节点资源不足、管理端不可用或证书续期异常。

## 发布后检查

仓库中的 `scripts/verify-safeline-rollout.sh` 只做无害的用户路径检查，不发送 SQL 注入、XSS 或其他攻击载荷，避免把验证脚本本身变成生产阻断源。它验证通过并不等于 SafeLine 已安装，只说明指定公网入口仍能正确提供费曼读书助手并保留基础安全边界。
