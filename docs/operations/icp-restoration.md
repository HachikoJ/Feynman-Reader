# ICP 备案后恢复指南

产品地址：https://reader.deline.top/ 。页脚备案号为“粤ICP备2025449309号-2”，链接至 https://beian.miit.gov.cn/ 。

本文说明备案后登录与 AI 渠道的配置、迁移边界和验收方法，不将本地测试结果视为外部 OAuth 或生产运行状态的证明。

## 运行模式与数据边界

备案后的正式模式启用观猹 OAuth 登录和 TokenDance AI 配置、授权及余额入口，关闭审核期临时用户名密码登录注册及 DeepSeek 官方渠道。该模式下，原密码账号的既有会话不能继续访问账号数据，用户需要使用观猹登录；官方 Key 也不能直接用于 TokenDance。

用户可在账号中心主动合并原密码账号数据。合并是一次性操作，完成后原账号凭据及会话停用。部署只切换程序和配置，不批量合并账号、不恢复历史内容，也不清空现有用户数据。

学习数据继续保存在现有 PostgreSQL，IndexedDB 用于历史本机数据迁移。旧数据尚未迁移时，不应清除浏览器网站数据。产品使用独立域名，不因备案恢复修改其他网站或重新启用退役入口。

## 配置与发布准备

登录与 AI 渠道切换会影响用户现有会话，应按已确认的范围执行。发布前保存当前应用版本、服务器环境和 Nginx 配置，并完成可恢复的数据库备份。核对服务器已有源码改动和发布脚本的历史版本保留策略，保留必要的回退资产。

在受保护的服务器环境文件中保留现有凭据，配置正式模式：

```dotenv
FEYNMAN_WATCHA_OAUTH_ENABLED=true
FEYNMAN_TOKENDANCE_ENABLED=true
FEYNMAN_DEEPSEEK_OFFICIAL_ENABLED=false
NEXT_PUBLIC_FEYNMAN_LOCAL_AUTH_BYPASS=false
FEYNMAN_PUBLIC_ORIGIN=https://reader.deline.top
```

`FEYNMAN_PUBLIC_ORIGIN` 必须与用户实际访问的 HTTPS 来源一致。检查 DNS、证书覆盖域名、反向代理 Host 和 HTTPS 转发信息；不能用健康检查成功代替登录及来源策略验收。

确认以下服务端凭据存在，不在构建日志或公开仓库中输出它们：

- `TOKENDANCE_OAUTH_CLIENT_ID`
- `TOKENDANCE_OAUTH_CLIENT_SECRET`
- `FEYNMAN_AUTH_STATE_SECRET`
- `FEYNMAN_API_KEY_ENCRYPTION_KEY`

`TOKENDANCE_OAUTH_REDIRECT_URI` 必须与观猹后台登记的登录回调地址完全一致：

```text
https://reader.deline.top/api/auth/tokendance/callback
```

登录回调由 `src/lib/server/authConfig.ts` 定义。TokenDance API Key 授权是另一条流程，其返回地址不能替代观猹登录回调。更换产品域名时须同步检查两类回调与应用归因配置，不能仅修改浏览器跳转地址。

管理员仍仅绑定 Wilson。服务器须同时配置 `FEYNMAN_ADMIN_USER_ID` 和 `FEYNMAN_ADMIN_PROVIDER_SUBJECT`，分别对应已核验的应用账号 UUID 与不可变观猹身份；缺失或不匹配时拒绝管理员访问。这两个值不得提交到公开文档或源码。角色、MFA 和管理操作细节见 [管理员数据浏览与操作](admin-data-browser.md)。

## 发布执行

在已同步并通过相关测试的项目目录执行 `bash deploy.sh`。脚本同步服务端与 `NEXT_PUBLIC_` 开关，执行数据库迁移、管理员约束检查、生产构建和发布。只重启进程不会更新编译进浏览器资源的公开开关。

管理员数据功能包含 `013_admin_data_changes.sql` 增量迁移，新增加密操作存档表，不修改既有学习记录。部署时应核验应用账号对新表的实际访问能力及浏览器角色隔离，不能把迁移命令退出成功当作全部功能验收。

保存发布与回退所需日志，但不要保存完整环境文件内容、密钥、认证器初始化 URI 或用户正文到公开产物中。

## 发布后验收

1. 首页、登录页、隐私页、manifest 和健康接口通过 HTTPS 正常响应。桌面与手机页脚备案号完整可见，链接到工信部网站。
2. 访客可查看系统示例；正式模式登录页显示观猹入口，密码登录和注册 API 不再接受新登录。
3. 登录入口跳转到 `https://watcha.cn/oauth/authorize`，回调、state 和 PKCE 正确。使用授权的真实测试账号完成授权、回跳、刷新后会话保持及退出验证。
4. 设置仅显示正式配置的 TokenDance 渠道。使用授权的测试账号验证 Key 授权、余额查询和请求归因；实际 AI 调用或充值按对应费用授权执行。
5. 使用隔离账号验证原账号合并的凭据校验、事务、一次性限制和旧会话失效；不要为了验收合并真实用户账号。
6. 书架、完整 AI 分析、练习、问答及笔记在重新进入与刷新后保留。读取异常时不应以空数据覆盖云端；未配置 TokenDance 时应显示可理解的配置提示。
7. 退役入口继续保持既定状态，新旧静态资源及安全响应头通过现有部署检查。
8. 管理员双重身份绑定、MFA、页面与脚本隔离以及写请求同源校验通过。管理页面与接口保持 `same-origin` 来源策略，不能通过接受 `Origin: null` 解决动态验证码表单错误。

真实观猹 OAuth、TokenDance 授权及管理员 MFA 需要部署后的真实账号验证。自动化模拟、健康探针和构建成功只能证明各自覆盖的部分；未执行的外部链路必须明确标为未验证，不能据此声称完整登录或计费链路通过。

## 回退

发布失败时保留诊断日志和失败版本，恢复切换前保存的应用版本、服务器环境与 Nginx 配置，校验后重载应用进程和代理。现有发布脚本的错误回退不自动撤销先前手动修改的服务器环境，因此环境文件须与旧应用版本配套恢复。

如需恢复审核期模式，应在确认的回退范围内使用对应旧构建与原配置；不能只切换部分开关而混用新旧登录、AI 渠道和浏览器资源。已完成的账号合并不能通过开关撤销，已发生的管理员数据操作也不会随代码回退自动撤销。不要通过覆盖上线后的数据库或清除浏览器数据来回退界面，保留操作存档、审计及其加密密钥。
