# 管理员数据浏览与操作

本文说明管理员后台的配置、数据范围、安全边界与发布验收。管理员仍仅绑定 Wilson 的账号；身份值由服务器环境提供，不写入源码、公开文档或浏览器配置。

## 入口与数据范围

Wilson 在个人中心进入“系统管理”，完成动态验证码验证后使用统计看板、用户数据、数据表、访问日志和操作历史。后台可以查看各用户的完整业务记录，包括已合并账号、回收站内容和迁移状态。

用户身份统一展示头像、昵称和用户名，UUID 作为区分同名用户的辅助信息。所有查询、权限判断和操作仍按 UUID 定位。资料按当前页面批量读取，只返回展示所需字段；名称与头像依次使用账号主资料、自定义资料和观猹资料，无头像时显示占位图。

| 表 | 可读内容 |
| --- | --- |
| app_users | 用户基本资料、观猹身份、联系方式及验证状态、注册时间、合并与停用状态；密码只显示是否设置 |
| user_books | 书籍资料、上传文档正文、六阶段 AI 分析、练习、问答、笔记、推荐、阅读进度、任务状态及回收站标记 |
| user_settings | 阅读与 AI 偏好、金句、个人资料；凭据字段脱敏 |
| user_ai_usage | 请求任务、模型、输入与输出用量、关联书籍与会话、时间及业务字段 |
| user_book_lists | 书单、书籍集合、说明和时间 |
| user_book_relations | 书籍关系、方向、备注和时间 |
| user_assistant_sessions | 助手会话、完整消息、关联书籍和时间 |
| user_assistant_memories | 长期记忆、分类、来源会话和时间 |
| user_behavior_events | 行为类型、时间及业务详情 |
| user_aux_data | 按命名空间保留的历史辅助数据 |
| user_data_state | 同步版本、导入时间、迁移状态与错误 |
| auth_sessions | 登录会话的创建、使用、到期与撤销状态，不返回会话凭据或哈希 |
| api_key_records | 提供方、配置状态和时间，不返回密钥及密文 |
| admin_roles | 管理员身份绑定、角色、授予与撤销状态 |
| admin_totp_credentials | 动态验证启用、绑定、使用、失败次数及锁定状态，不返回认证密钥 |
| admin_recovery_codes | 恢复码的创建与使用状态，不返回码值或哈希 |
| admin_sessions | 管理员会话的认证、到期与撤销状态，不返回令牌或哈希 |
| admin_audit_logs | 管理员操作、目标用户、时间、请求标识和脱敏详情 |
| admin_daily_metrics | 已保存的历史指标，没有记录时显示空状态 |

上述业务与管理表使用固定目录浏览；`admin_data_changes` 仅通过独立“操作历史”展示变更元信息，不进入通用数据浏览器，不返回加密快照。

列表支持中文搜索、用户及时间筛选、分页和固定排序。常用字段使用中文列名，完整 JSON 按需在详情中读取；不会因列表摘要而截断或覆盖学习正文。筛选和记录定位保存在 URL 中，支持返回与刷新。读取失败与空记录分别处理，不把错误显示为空书架。

## 服务器配置

| 环境变量 | 用途 |
| --- | --- |
| `FEYNMAN_ADMIN_USER_ID` | Wilson 已核验的应用账号 UUID |
| `FEYNMAN_ADMIN_PROVIDER_SUBJECT` | 与该账号对应的不可变观猹身份 |
| `FEYNMAN_PUBLIC_ORIGIN` | 管理员请求允许的完整 HTTPS 来源，须与实际访问域名一致 |
| `FEYNMAN_AUTH_STATE_SECRET` | OAuth 状态签名及管理会话记录的不可逆定位标识 |
| `FEYNMAN_API_KEY_ENCRYPTION_KEY` | 服务端密钥和操作存档的加密密钥 |
| `DATABASE_URL`、`DATABASE_SSL_CA` | 服务端数据库连接与按部署环境配置的证书 |

两个管理员身份变量必须同时配置，缺失或不匹配时拒绝管理员访问。不得以显示名、用户名或前端传入值替代身份绑定，也不得使用 `NEXT_PUBLIC_` 变量存放身份配置或任何秘密。

身份变量必须与 `app_users` 和有效 `super_admin` 角色记录一致。配置环境变量本身不会创建管理员角色或完成 MFA 绑定。新部署按 `scripts/bootstrap-admin.mjs` 的初始化流程绑定认证器；已有部署保留原有角色、TOTP 和恢复码，不因升级重复初始化。初始化产生的密钥与恢复资料只通过受控渠道保存，不写入日志、截图或仓库。

## 访问隔离与来源策略

管理页面由服务端渲染。普通登录会话、环境中的双重身份绑定和有效 `super_admin` 角色同时匹配后，才返回管理员入口；未登录和其他账号访问管理页面时返回 404。数据读取和操作还要求有效的管理员 MFA 会话。

管理业务代码保留在服务端。Nginx 对 `/admin` 页面以及 `/_next/static/chunks/app/admin/` 下新旧管理脚本执行身份授权子请求；其他账号无法通过直接 URL 下载这些管理资源。子请求仅转发配置的 Host 和 Cookie，避免浏览器 RSC 等内部路由头改变授权结果。通用前端的入口可见性检查不承载权限决定；已被客户端下载的旧资源不能通过后续部署撤回。

MFA cookie 使用 `Path=/`，保持 HttpOnly、生产环境 Secure 和 SameSite=Strict。旧版 `Path=/api/admin` cookie 在成功验证后清除；升级后出现重新验证提示时，输入认证器的当前动态验证码。

管理员写请求必须通过来源校验。设置 `FEYNMAN_PUBLIC_ORIGIN` 为真实服务域名，在 `/admin`、`/api/admin` 响应及管理页面 metadata 中使用 `Referrer-Policy: same-origin`；其他页面可继续使用更严格的策略。个人中心管理入口使用完整页面导航，避免继承旧文档策略导致原生表单发送 `Origin: null`。出现“请求来源无效”时检查域名、反向代理响应头和文档策略，不允许通过接受 null 或跨站来源解决。

接口使用固定表与字段白名单、参数化查询及有限分页，不接受任意 SQL。敏感字段在服务端投影与递归脱敏，正常学习文本保持完整。管理响应使用 `Cache-Control: no-store`；访问日志仅记录操作元信息，不复制正文或凭据。

## 操作与恢复

| 对象 | 允许操作 |
| --- | --- |
| 普通用户账号 | 修改昵称及联系方式、停用和启用；修改联系方式会清除对应验证状态 |
| 书籍、设置、书单、书籍关系、助手会话与记忆、辅助数据 | 按记录编辑、删除和恢复；关联书籍须属于同一账号 |
| API 密钥配置 | 撤销授权，不可恢复；不显示或编辑密钥 |
| 登录会话、管理员身份和认证配置、用量、事件、同步状态、审计与历史指标 | 查看安全投影，不通过通用编辑器改写 |

Wilson 自身的身份记录及已合并账号禁止通用编辑与启停。普通账号停用后，其现有登录会话也无法访问账号数据。密码、身份绑定和各类凭据由服务端保护，查看与编辑共享敏感字段判断。

每次操作先显示目标、影响和恢复方式，再要求输入“确认”。写事务再次锁定并核实唯一管理员身份。操作存档、实际修改和审计在同一事务提交，版本冲突时拒绝覆盖。

操作前后快照使用服务端加密密钥加密保存。书籍删除进入 30 天回收站；其他可删除业务记录逐条归档后删除。“操作历史”可恢复允许撤回的变更；若记录已有后续修改则拒绝覆盖，成功恢复时推进版本与更新时间。API 授权撤销不能通过操作历史恢复。

备份数据库时同时保管对应加密密钥。丢失或直接替换加密密钥可能导致已有密钥记录及操作存档无法解密；轮换前须验证旧数据的解密与迁移方案。

## 部署与增量迁移

部署前保存当前应用版本、服务器环境、Nginx 配置和可恢复的数据库备份。使用现有 `deploy.sh` 完成构建、校验、迁移和发布，核对其历史版本保留策略后执行。

`supabase/migrations/013_admin_data_changes.sql` 只新增管理员加密操作存档表。部署脚本通过 `scripts/apply-admin-data-migration.mjs` 执行并检查结构、RLS 和访问权限，不恢复历史学习内容，不批量修改现有业务记录。脚本可重复运行。

迁移需要足够的数据库 DDL 权限。运行账号应能读取、插入和更新存档表，同时浏览器角色 `anon`、`authenticated` 不得拥有表权限。还须验证运行账号的 RLS 访问能力：只有 GRANT 并不保证开启 RLS 且没有策略的表可用。迁移脚本在本机特权重试前会回滚失败事务以释放锁；其他环境应由部署方使用适当的数据库管理身份执行迁移，随后重新验证应用账号。

发布后使用应用实际数据库账号检查操作历史可读；新安装的存档表应返回空页，升级实例则保留已有历史。不要为了验证编辑和恢复而修改真实用户记录。

## 验收与回退

1. 检查身份变量缺失、身份不匹配、普通账号、未登录、失效会话及未完成 MFA 的访问均被拒绝，不能返回记录片段。
2. 检查页面、RSC 请求和新旧管理脚本的直接访问隔离；接口未登录与跨来源写请求按约定拒绝，响应不缓存。
3. 检查所有数据目录、搜索、分页、完整详情和用户头像信息；同名用户按 UUID 区分，缺失或无效头像有可用占位图。
4. 检查凭据在接口、编辑表单、原始 JSON 和日志中均未泄露；读取失败不能替换为虚构空数据。
5. 使用模拟数据或隔离数据库覆盖编辑、删除、恢复、版本冲突、账号隔离和存档加密；数据库临时表测试必须保证实际业务表不可写。
6. 检查桌面与手机、深浅主题、中文状态、宽表滚动和长正文；运行相关单元与接口测试、类型检查、构建、Nginx 配置校验及 `git diff --check`。
7. 部署后核验 HTTPS、健康接口、资源隔离及真实管理员 MFA 登录。模拟身份或布局测试不能替代真实账号认证验收。

应用回退时恢复上一版应用、匹配的服务器环境与 Nginx 配置，再验证访问隔离和来源策略。代码回退不会撤销管理员已确认的数据操作；需要恢复的记录应通过操作历史逐条处理，并遵守版本冲突保护。保留新存档表、审计及其加密密钥，不通过删表或覆盖整库完成界面回退。
