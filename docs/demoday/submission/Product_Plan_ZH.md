# AI 费曼读书助手：结课产品方案

## 0. 项目摘要

**产品名称：** AI 费曼读书助手（Feynman Reader）  
**一句话介绍：** 读完一本书后，用自己的话讲给 AI 听；AI 不替用户总结，而是通过阶段化学习、评分和 3 个角色追问，找出讲不通的地方，直到用户能讲清楚。  
**当前形态：** 可运行的 Next.js Web Demo，AI 服务使用 DeepSeek V4 Flash，学习数据默认保存在浏览器 IndexedDB。

本项目的核心不是“让 AI 帮我读完一本书”，而是建立一个强制输出的练习闭环：**输入资料 -> 形成自己的解释 -> 接受追问与评分 -> 根据反馈重答 -> 留下可复盘记录**。

## 1. 需求来源

我有过这样的学习失败：花两周读完一本技术书，读完时以为都懂了，别人一问“这本书讲了什么”，却讲不出三句话。问题不是资料不够，而是没有人要求我把理解说清楚，也没有人指出我到底错在哪里。

费曼学习法给出了一条很朴素的标准：能用大白话解释，才算真正理解。但一个人练习时有两个缺口：

1. 没有听众，就容易跳过输出。
2. 没有反馈，就无法判断解释是否准确、完整和清晰。

因此产品把 AI 定位为“装傻但懂行的陪练”：它拥有书籍原文与评分标准，但不直接替用户完成思考；它用问题、评分和改进建议把用户推回自己的表达。

## 2. 目标用户与核心场景

| 目标用户 | 典型痛点 | 产品切入点 |
| --- | --- | --- |
| 学技术、考证、读专业书的人 | 读完很快忘，解释时卡壳 | 教学模拟 + 原文依据评分 |
| 希望提升表达与批判思考的人 | 笔记多，但观点无法经受追问 | 角色问答 + 具体改进建议 |
| 有系统阅读习惯的知识工作者 | 需要沉淀学习记录并复盘 | 六阶段学习记录 + 本地数据管理 |

核心场景：

1. **读完心里没底**：用户把一本书讲给 AI 听，确认自己是否真的理解。
2. **复杂概念讲不通**：用户先查看 AI 的阶段分析，再换成自己的语言解释。
3. **想查漏洞而非要摘要**：AI 从初学者、职场角色、专家等不同视角提出追问，帮助发现概念与逻辑边界。

## 3. 产品定位与设计原则

**定位：** 面向深度阅读的 AI 练习场，而不是摘要工具或聊天陪伴工具。

| 设计原则 | 落地方式 |
| --- | --- |
| 用户输出优先 | 教学模拟要求用户输入至少 200 字；AI 只在用户表达后评分。 |
| 反馈必须可行动 | 未通过记录保留原答案、分数和具体改进建议，用户据此重答。 |
| 通过状态由规则控制 | 客户端按 60 分阈值计算题目通过，不直接信任模型返回的 `passed`。 |
| 完成不能被平均分掩盖 | 角色问答固定 3 题，必须全部通过才进入综合得分和“已读”状态。 |
| 本地优先与知情同意 | API Key、书籍与学习记录保存在本地；用户在调用 AI 前必须完成隐私同意。 |

## 4. 当前已实现的产品能力

### 4.1 书架与资料输入

- 创建、编辑、删除书籍，按阅读状态、标签、分类筛选。
- 支持 PDF、Word、Excel 等文档解析，并把截取后的文本作为 AI 评估的知识依据。
- 显示书籍的在读/已读状态、学习阶段进度和综合得分。
- 书架提供阅读状态分布、得分分布和标签筛选。

### 4.2 六阶段学习

已实现的顺序学习主流程包含：

1. 背景探索：作者、时代与写作动机。
2. 全书概览：建立核心框架。
3. 深度拆解：以教代学，识别核心概念。
4. 辩证分析：主动寻找逻辑漏洞与反例。
5. 众声回响：理解评价与影响。
6. 融会贯通：连接已有知识并思考应用。

每个阶段由 AI 生成 Markdown 内容，支持折叠查看重点。完成状态按阶段保存，完成全流程后书架显示完整进度。

### 4.3 费曼实践：教学模拟与角色问答

这是当前产品最重要的闭环。

**教学模拟**

- 用户以“教给完全不懂的人”的方式输入自己的解释。
- AI 依据书籍原文，从准确度、完整度、清晰度和综合表现四个维度评分。
- 评分结果和 AI 点评保存为实践记录，可回看具体维度。

**角色问答**

- AI 根据用户的教学模拟内容生成 **3 个**不同角色的问题。
- 用户回答后，AI 给出逐题分数和点评；未通过时，当前题目与问答记录中都会展示原回答和改进建议。
- 所有 3 题都达到 60 分后，问答才算完成。未完成的问答不展示平均分为“综合成绩”，也不计入书籍最终得分。
- 评估回写使用角色标识而不是模型返回顺序，避免多题结果错配。

### 4.4 使用控制与隐私

- 10 次试用计数、机器码和激活码流程已实现，用于限制浏览器端 Demo 的 AI 调用次数。
- API Key 输入框默认掩码显示，设置中明确提示 Key 仅保存在本地浏览器。
- 用户必须勾选并阅读隐私政策后，才能保存 AI 设置并调用 AI 功能。
- 数据管理和金句管理入口集中在设置页，支持本地数据导入/导出。

## 5. 核心交互流程

```text
书籍 / 本地文档
  -> 用户确认 AI 数据使用并配置自己的 API Key
  -> AI 生成六阶段学习内容
  -> 用户阅读、记录并完成阶段
  -> 用户提交教学模拟
  -> AI 评分与指出理解漏洞
  -> AI 生成 3 个角色问题
  -> 用户逐题回答与修订
  -> 3 题全部通过
  -> 更新“已读”、综合得分与可复盘记录
```

### 用户与 AI 的分工

| 用户负责 | AI 负责 |
| --- | --- |
| 选择书、上传资料、阅读与用自己的话表达 | 根据书名、原文和当前学习输出构建学习提示 |
| 选择是否采纳建议、修订答案、掌控隐私授权 | 生成六阶段分析、评分、角色问题与具体改进建议 |
| 形成最终理解 | 暴露理解漏洞，而不是替用户声称“已经理解” |

## 6. AI 工作流程与数据边界

### 输入与处理

1. 用户输入书名、作者、可选文档，以及阶段学习或实践文本。
2. 客户端先校验是否已同意 AI 数据使用；没有同意则不创建 DeepSeek 客户端。
3. AI 调用会携带与任务相关的书籍信息、截取后的原文和用户当前输出。
4. AI 返回阶段分析、教学评分或角色问题；客户端校验评分范围和通过阈值。
5. 结果写入 IndexedDB，供书架、实践记录和问答历史读取。

### 需要用户确认的节点

- 保存并使用 API Key 前确认数据传输同意。
- 隐私政策必须滚动阅读到末尾后确认。
- 用户可自主决定是否提交教学内容、是否重答、是否删除/导出本地记录。

### 安全与限制

当前是本地优先 Demo，而不是服务端多租户 SaaS：API Key 和学习记录在浏览器中保存，调用由浏览器直接发往 DeepSeek。10 次试用与激活机制用于 Demo 体验控制，仍是客户端逻辑，不能当作生产级授权安全方案。

## 7. Day 1-3 设想与当前状态

| 早期设想 | 当前状态 | 说明 |
| --- | --- | --- |
| 用户用大白话讲给 AI 听 | 已实现（文本） | 教学模拟要求至少 200 字，AI 评分并给出点评。 |
| AI 装傻追问 2-3 轮 | 已实现为结构化 3 角色问答 | 不是实时多轮语音对话，而是 3 道不同视角的追问与重答闭环。 |
| 拍书/粘贴内容 | 部分实现 | 支持创建书籍、上传并解析文档；拍照 OCR 尚未实现。 |
| 4 种学习模式 | 配置层已存在，主流程未接入 | 当前线上主路径是顺序 6 阶段，不把模式选择写成可用功能。 |
| 语音解释 | 未实现 | 当前只支持文本输入。 |
| 隔天自动提醒、遗忘曲线复习 | 未实现 | 有偏好配置与学习方法代码，但没有可用的提醒调度和通知闭环。 |
| 10 次试用 + 机器码激活 | 已实现（浏览器端 Demo） | 用于体验限制，不是生产级反破解能力。 |
| 用户时长/复用验证 | 待验证 | 暂无可对外宣称的用户研究样本或留存数据。 |

## 9. 预期收益与验证指标

### 用户价值假设

- 用户能更快发现“自以为懂了”的概念与逻辑漏洞。
- 角色问答会促使用户从复述转向解释、举例与批判性思考。
- 实践记录让复习从再次翻书变成对薄弱点的定向回看。

### 下一阶段需要验证的指标

| 假设 | 可观察指标 |
| --- | --- |
| 用户愿意输出 | 首次完成教学模拟的比例、平均字数、角色问答完成率。 |
| 反馈有帮助 | 未通过题二次提交率、二次通过率、用户主观“知道怎么改”评分。 |
| 产品形成复习价值 | 同一本书 7 天内回访率、再次实践率、阶段记录阅读率。 |
| AI 评分足够可信 | 人工评分与 AI 评分的一致性、错题反馈的可操作性评价。 |

## 10. 项目复盘与下一步

### 开发方式与收获

项目以 Vibe Coding 的多轮迭代完成：先搭建 Next.js 页面与前两阶段分析，再补齐六阶段、文档解析、费曼实践、评分和使用控制。最大的收获是：AI 产品不是“接上模型接口”就结束，评分规则、状态机、错误反馈、隐私同意和数据持久化决定了体验是否可信。

### 已解决的关键问题

- 多题评估可能乱序：改为通过角色标识回写题目。
- 未通过答案容易被隐藏：改为直接展示用户回答、分数与改进建议。
- 局部平均分掩盖未完成状态：只有整组 3 题通过才计算综合得分。
- AI 同意提示不在操作现场：在 API Key 保存和调用链路中强制校验，并引导到隐私政策确认位置。

### 下一步优先级

1. 用真实用户测试验证输出意愿、二次提交率和反馈有效性。
2. 增加真实的语音输入/转写，让“讲给 AI 听”更接近原始设想。
3. 把间隔复习做成可执行的本地提醒与复习队列，而非仅保留配置概念。
4. 将学习模式选择真正接入阅读主流程，或删除未接入能力，避免认知负担。
5. 对授权与试用逻辑迁移到服务端，避免生产环境把密钥或授权判断留在浏览器。
