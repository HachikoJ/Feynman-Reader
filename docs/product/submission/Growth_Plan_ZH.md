# AI 费曼读书助手：增长方案

## 1. 我想怎么增长

我不想把它做成一个“帮你快速总结一本书”的工具，因为这类工具已经很多了。这个产品真正有意思的地方是：你要自己讲，AI 再用 3 个不同角色追问你，逼你发现哪里其实没懂。

所以前期我会先去技术学习、考证、读书会这些社群里找 30 个种子用户。可以做一个“7 天讲清一本书”的小挑战：每个人选一本自己正在读的书，完成一次教学模拟和 3 个角色问答。

我会重点看两件事：

- 有多少人真的愿意写 200 字以上，把知识讲出来。
- 被 AI 指出问题后，有多少人愿意回来重答。

之后可以做一张可分享的学习成果卡，只放书名、得分、3 题是否通过和一条 AI 建议，不公开用户的原回答。这样用户愿意晒自己的学习成果，也能让别人更容易理解产品是干什么的。

我给自己定的核心指标是：**每周完成一次“教学模拟 + 3 题全部通过”的用户数。** 这比单纯看打开次数更有意义。

## 2. 定价想法

现在这个产品由用户自己填写 DeepSeek API Key，学习记录和 Key 也默认保存在自己的浏览器里。所以当前最适合的方式不是一上来做订阅，而是先做一个本地版：

| 版本 | 价格 | 说明 |
| --- | ---: | --- |
| 体验版 | 免费 | 先体验完整的教学模拟和角色问答流程 |
| 本地版 | 29 元一次性 | 用户自带 API Key，可以无限保存书籍、学习记录和导出数据 |
| Pro 版 | 39 元/月（后续再做） | 平台提供 AI 额度、云同步和复习提醒 |

我认为先卖本地版更合理：用户自己承担模型费用，产品也不用为了“免费无限 AI”承受很高成本。等验证用户真的会回来复习、也愿意付费后，再做 Pro 版。

## 3. Token 成本怎么控制

当前产品里，六阶段分析、教学模拟评分和角色问答都会调用 AI。最大的问题是：如果每一步都把整本书塞给模型，成本会越来越高。

我准备这样控制：

1. 上传文档后先切成小段，每次只给 AI 最相关的几段，不重复传整本书。
2. 同一本书的六阶段结果生成过一次就缓存，用户没改资料就不重复生成。
3. 角色问答重答时，只重新评分改过的那一题。
4. 给每种功能单独限制输出长度，避免模型写很长但用户不看的内容。
5. 以后做 Pro 版时，按“完整练习包”给额度，而不是无限调用。一个练习包就是六阶段、一次教学评分、出 3 题和一次问答评分。

现在项目里的 `deepseek-v4-flash` 单价我不会写死，因为模型价格可能变。正式上线后应该在服务端记录每次调用的输入 Token、输出 Token 和任务类型，再按当时官方价格计算成本。

## 4. 怎么验证 PMF

我不会一开始就认为大家会喜欢。先找 30 个真实用户，用 4 周做小测试：

- 第 1 周：看多少人完成第一次教学模拟。
- 第 2 周：访谈没完成的人，看看是哪里卡住了。
- 第 3 周：让用户回来重讲一次，看看有没有真的提高。
- 第 4 周：问他们“如果这个产品不能用了，你会不会很失望”，同时测试 29 元本地版有没有人愿意付费。

我暂时给 PMF 定几个简单标准：

- 35% 的人能在第一次使用当天完成教学模拟。
- 20% 的人能在 7 天内完成 3 个角色问答。
- 没通过的人里，至少一半愿意重答。
- 7 天后还有 25% 的人回来继续学或开始第二本书。
- 至少 40% 的调研用户说“没有它会很失望”。

如果这些数据达不到，我不会急着投流或加很多功能，而是先回去看：是不是第一次让用户写得太难、AI 的反馈不够具体，还是“角色追问”并没有真的帮到用户。
