# 第 7 天作业：AI 费曼读书助手的增长想法

## 先从哪儿找人

我不准备把它包装成“几分钟读完一本书”的工具。这个产品有点反着来：用户得自己讲，AI 再追问。愿意做这件事的人，才会留下来。

前期先去技术学习群、考证群和读书会里找 30 个种子用户，做一个「7 天讲清一本书」的小挑战。参与者选一本正在读的书，至少完成一次教学模拟和 3 个角色问答。

我主要看两件事：

- 第一次打开后，有多少人愿意写完 200 字的教学模拟。
- 被指出问题后，有多少人会回来重答。

后面可以加一张学习成果卡，放书名、得分、3 题是否通过和一条建议，不放用户原回答。晒出去不尴尬，别人也能一眼看明白这产品是干什么的。

我更在意每周有多少人完成「教学模拟 + 3 题全部通过」，而不是单纯打开了多少次。

## 怎么收费

现在用户自己填 DeepSeek API Key，书和学习记录也留在自己的浏览器里。这个阶段先卖本地版，比一上来收订阅更顺。

| 版本 | 价格 | 内容 |
| --- | ---: | --- |
| 体验版 | 免费 | 先走完一遍教学模拟和角色问答。 |
| 本地版 | 29 元一次性 | 用户自带 API Key，能保存书、记录和导出数据。 |
| Pro 版 | 39 元/月，后面再做 | 平台提供 AI 额度、云同步和复习提醒。 |

本地版先把产品价值讲清楚，模型费用由用户自己承担。等有人真的会回来复习、也愿意付钱，再考虑 Pro。

## Token 怎么省

六阶段分析、教学评分和角色问答都会调模型。要是每次都把整本书塞进去，账单很快就不好看。

我准备这么做：

- 文档先切段，每次只带最相关的内容。
- 同一本书的六阶段结果生成过一次就缓存，资料没变就不重跑。
- 重答角色题时，只评分改过的那一题。
- 限制每个任务的输出长度，别让模型写一大段用户根本不会看的话。

以后做 Pro，不卖无限调用，按「完整练习包」给额度。一个练习包包含六阶段、一次教学评分、出题和一次问答评分。

`deepseek-v4-flash` 的价格会变，我不在作业里硬写成本。真做服务端后，再按任务类型记输入和输出 Token，按当时价格算。

## 怎么判断值不值得继续做

先找 30 个人跑 4 周，不急着投流。

- 第 1 周，看有多少人完成第一次教学模拟。
- 第 2 周，找没完成的人聊聊，看看是卡在输入、反馈，还是流程太长。
- 第 3 周，让已经学过的人回来重讲一次，看他们有没有真的变清楚。
- 第 4 周，问他们愿不愿意花 29 元买本地版，也问一句「它没了你会不会觉得可惜」。

我先用下面几个数判断：

- 35% 的人当天能完成教学模拟。
- 20% 的人 7 天内完成 3 个角色问答。
- 没通过的人里，至少一半会重答。
- 7 天后还有 25% 的人回来继续学，或者开始第二本书。
- 40% 的访谈对象说没有它会觉得可惜。

这些数要是不好看，我不会马上加功能。先回头看第一步是不是太难，AI 的反馈是不是太空，角色追问到底有没有帮上忙。
