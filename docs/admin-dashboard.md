# 系统管理员看板

管理员看板只允许经过授权的系统管理员访问，普通账号即使知道地址或修改前端参数也不能获得权限。

## 首次初始化

先完成 `011_admin_security.sql` 迁移，再在服务器本地执行一次初始化。目标账号必须已经存在、处于可登录状态并绑定观猹主体：

```bash
set -a
. /etc/feynman-reader.env
set +a
ADMIN_USER_ID='填写 app_users.id' npm run bootstrap:admin
unset ADMIN_USER_ID DATABASE_URL FEYNMAN_API_KEY_ENCRYPTION_KEY
```

命令会输出一次性认证器 URI 和备用密钥。请只在受控终端导入认证器，不要将输出写入日志、工单或 GitHub。初始化脚本不会创建公开管理员注册入口。

## 身份唯一性

观猹回调只把用户信息接口返回的 `data.user_id` 作为稳定主体标识，写入 `app_users.tokendance_subject`；该字段由数据库唯一索引约束。昵称、姓名和头像仅用于资料展示，多个账号同名不会合并，也不会获得管理员权限。管理员角色同时绑定账号 UUID 和该主体标识，任一字段不匹配都会拒绝访问。

每次部署都会自动执行管理员迁移和安全校验，检查账号主体唯一索引、管理员主体非空约束、重复主体以及角色与账号主体是否一致；不需要手动打开数据库工具执行 SQL，校验失败会中止部署。

## 日常使用

先使用普通账号登录，再访问 `/admin`，输入认证器的 6 位动态验证码。管理员会话使用独立的 HttpOnly、Secure、SameSite=Strict Cookie，最长 8 小时；退出后服务端会撤销该会话。

看板只返回用户数、书籍状态、阶段分布、AI 用量、行为事件和存储容量等聚合指标，不返回邮箱、手机号、密码哈希、API Key、完整书籍正文、附件、原始聊天或完整 AI 回复。管理员访问会写入最小化审计日志。

## 运行边界

管理员运行账号应使用无 `BYPASSRLS`、无 DDL 权限的数据库角色；迁移和初始化使用单独的数据库管理员身份。请定期轮换服务器密钥、认证器和数据库凭据，并限制服务器 SSH 权限。

如果服务器 root、数据库超级用户或管理员设备本身已被攻破，应用层无法保证绝对安全；发现异常时应立即撤销管理员角色、删除活动会话并轮换密钥。
